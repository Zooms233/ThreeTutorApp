```dart
class _HomePageState extends State<HomePage> {
  int pageIndex = 0;
  final pages = [TabChat(), TabContact(), TabSetting()];

  @override
  Widget build(BuildContext context) {
    return Scaffold(
      body: pages[pageIndex],
      bottomNavigationBar: NavigationBar(
        destinations: [
          NavigationDestination(icon: Icon(Icons.chat_bubble), label: '聊天'),
          NavigationDestination(icon: Icon(Icons.contacts), label: '通讯录'),
          NavigationDestination(icon: Icon(Icons.settings_applications), label: '设置'),

        onDestinationSelected: (tappedIndex) {
          setState(() {
            pageIndex = tappedIndex;
          });
        },
      ),
    );
  }
}
```

## 学到的东西

### Flutter 工程基础

- **平台选择**：`--platforms windows,android` 指定目标平台。不考虑 web 是因为文件读写需要直接访问本地文件系统，而 web 运行在浏览器沙箱里做不到。
- **热重载 vs 热重启**：热重载保留应用状态（比如计数器的数值），热重启从头再来。开发中前者更常用、更快。
- **目录分层**：约定 `lib/` 下按职责分目录，本次项目统一用**不加 s 的单数**命名确保一致性：

```
   lib/
   ├── main.dart        # 入口
   ├── page/            # 界面层：一个页面一个文件
   ├── service/         # 服务层：数据读写、外部能力
   ├── model/           # 数据模型（纯数据结构）
   ├── widget/          # 可复用小部件（多个页面共享的零件）
   └── util/            # 零散工具函数
```

### 组件与布局

- **Scaffold**：页面的骨架容器，`appBar` 是顶部标题栏，`body` 是主体内容。
- **Center / Column**：居中布局；Column 纵向排列多个子组件（`children` 列表），`mainAxisAlignment` 控制主轴对齐。
- **NavigationBar**：Material 3 的底部导航栏，配 `NavigationDestination`（icon + label）。`selectedIndex` 控制选中项，`onDestinationSelected` 接收点击回调。
- **StatelessWidget vs StatefulWidget**：无状态组件 build 一次就定型；要响应变化（如点击切换 tab）就用 StatefulWidget，靠 `setState(() {})` 通知重建。

### Dart 语言

- **StatefulWidget 的模板结构**：`createState() => _XxxState()`，状态写在私有类里。
- **字符串插值**：`$变量` 直接取值；`${表达式}` 可以放属性访问、方法调用等任意表达式。
- **Future / async / await**：异步方法返回 Future 类型，函数标记 `async` 后内部可用 `await` 等待结果，常用于文件读写。
- **命名规范**：

| 对象 | 风格 | 示例 |
| --- | --- | --- |
| 方法 / 变量 | 小驼峰 | `importBuiltinWorlds` |
| 类 / 类型 | 大驼峰 | `TabContact` |
| 常量 | 小驼峰（不是全大写） | `maxLines` |
| 文件 / 包名 | 全小写下划线 | `storage.dart` |
| 私有成员 | 小驼峰 + 下划线前缀 | `_expanded` |

### 资源与存储

- **assets**：打包进安装包的非代码文件，需在 pubspec.yaml 声明。注意**目录不递归包含子目录**，所以每个层级都要单独列：

```yaml
flutter:
  assets:
    - assets/worlds/教令院/
    - assets/worlds/教令院/TUTOR/
```

- **path_provider**：查找应用专属数据目录的插件（Android 是 `Android/data/<包名>/files/`，Windows 是 `AppData/Roaming/`），装完 `flutter pub add path_provider` 才能 import。
- **文本 vs 二进制**：`rootBundle.loadString()` / `File().writeAsString()` 按 UTF-8 处理文本；`rootBundle.load()` / `File().writeAsBytes()` 处理图片音频等二进制。

### 技术选型（通讯录页设计时定的）

- **数据格式**：json / jsonl 单文件存储。小项目读写频率低，相比数据库便于人类阅读。
- **页面顺序**：通讯录页 → 聊天页 → 设置页；大方向先搭页面，之后再处理 AI 逻辑。
- **ExpansionTile**：折叠/展开面板，通讯录分组展示时可用。

## 经验与反思

最深刻的失败是 storage.dart：任务难度明显超出当时的能力边界，AI 提示的每一句语法都要解释，一边记录一边写码让大脑过载，花了 3 个多小时在技术选型上，实际推进为 0，最后焦躁地清空了文件。

回头看这恰好印证了 00-重新出发 里的教训正在重演——**求快就会失控**。拿到什么新概念就想立刻用上，结果连"文件读写到底要几步"都没梳理清楚就动笔。

所以现在定了新的过程规则：**一次只完成一个函数或页面，用户审核通过后再提交**。把"理解"和"实现"拆开，先让计划落在代码里被看见，再决定要不要继续。节奏慢下来，掌控感才能回来。

下一步的方向是明确的：完成通讯录页（按设计方案做真实数据展示），之后是聊天页、设置页，最后接入 AI 逻辑。每完成一个可审核的单元，就回来记录一篇。
