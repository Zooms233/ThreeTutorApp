### 消息流

- 按需加载（主流 IM 行为）：进入渲染最近课次，凑满约一屏 20 条即停；上滑到顶逐个加载更早课次；全部加载完顶部「没有更多了」
- 物理行序即文件内时间序；渲染时按用户消息时间戳做块级稳定排序（键 = user 自身 time，tutor/tool 继承其前最近 user，meta 锚定其文件内首条 user，同键保持物理行序）——仅跨文件交界修正时序
- 分隔行：课次分隔行 `第 N 课 · 导师名 · MM-DD`（meta 行处，仅 UI 装饰）；「下课后」（本文件首条 social 消息前）；从未上课只显示「你加入了群聊，现在可以开始聊天了」
- 消息条目：GptMarkdown 渲染（标题/列表/`$...$`、`$$...$$` LaTeX、`_斜体_` 规范化为星号斜体）；导师消息头像在左（头像+名+气泡），用户消息右对齐（绿气泡不显示名字文本，头像框在气泡右侧、显示称呼首字）
- 消息正文字号 15 / 卡片 13（导出用），气泡最大宽度约屏宽 72%

### 消息流向（输入框发送去向，judgeFlow 三态判定）

| 最新课次 status | 切换按钮 ⇄ | 流向 | phase | 写入目标 |
|---|---|---|---|---|
| ongoing | 不显示 | 上课对话 | teaching | 最新课次文件 |
| idle · 未上过课 | 不显示 | 问答 | qa | 最新课次文件（下一课区间的交流段） |
| idle · 上过课 | 未激活（默认） | 问答 | qa | 同上 |
| idle · 上过课 | 激活 | 群聊讨论 | social | 上一课文件尾（群聊之后） |

- 问答：由 STATE.next_tutor 一对一回应，可参考教材（agent 翻书，工具机制见 [教学过程.md](../教学过程.md)）；讨论：三位导师依话题选人回应，靠发言者名自然区分
- 切换按钮仅 idle 且累计课时 ≥1 显示；切换状态仅会话内存（重启恢复默认不激活）

### 生成中状态（busy）

- service 静态表持有（课程名 → 文案），跨页面跨实例存活；退出重进仍显示并锁输入
- 输入框即状态位：hint 替换为 busy 文案并禁用（替代顶部 Banner）；[聊天页](tab_chat.md) 会话列表预览位同步绿色小字
- 文案序列：「正在输入中…」→ 拿到导师名后「{导师} 正在输入中…」/「群里正在输入中…」/「{导师} 正在翻阅教材…」/「整理课程进度中…」（下课流程全程）
- 生成结束从文件重载新内容；群聊逐条上屏队列（落档实时完成，UI 每 2 秒弹一条模拟真实节奏；发消息前一次性揭示剩余）

### 消息操作（长按 / 桌面右键）

```
┌──────────────────────────┐
│        ⧉ 部分复制         │  ← 全部消息可用
│        ⧉ 全部复制         │  ← 全部消息可用
│        ✎ 修改             │  ← 仅当前流最后一条用户消息
└──────────────────────────┘   深色半透明底部菜单
```

- 部分复制：进入选择模式——目标消息换 SelectionArea、输入条换提示条「拖选要复制的文本，选中后用弹出菜单复制」+「完成」；复制的是渲染后文本（所见即所得）
- 全部复制：复制 content 源文本（Markdown/LaTeX 原文）
- 修改：条件 = 非 busy、非修改/选择中、长按消息 = 当前流目标文件的物理最后一条 user 行（流判定与发送同源；social 指上一课文件尾，需 ≥2 个文件）；输入框继承原文全选 + 提示条「正在修改，发送后替换原消息并重新生成回复」，× 退出；flow 在点「修改」时定死（防中途切 ⇄ 漂移）
- 提交落档：service 改写目标文件物理最后一条 user 行（content、time = 编辑时刻）并截断其后所有行（本轮回复链），随后按原流拼装生成照旧；失败内容放回输入框保持修改模式（重试幂等）
- 安全性依据：该行之后只可能是本轮回复链（tool_call/tool/tutor）——auto 群聊行要么在别的文件、要么在该行之前

### 失败处理

- 发送/重生成失败（LlmException）：toast「发送失败：… 消息已保留，重新发送即可」/「重新生成失败：… 内容已放回输入框，可重试」；用户消息已留档（悬空），界面从文件重载校正；再发时连续合并消化
- 非 LlmException 异常同样 toast（不静默失败）
- 问候 / 课后更新失败的表现见 [课程详情页](course_detail_page.md)（meta 保持 ongoing 可重试，本页仅承接 toast）

数据存储（CHAT/第N课.jsonl，一文件 = 一个课次区间；行序即文件内时间序）

```jsonl
{"type":"meta","lesson":2,"date":"2026-08-04","tutor":"颜回","status":"idle"}
{"type":"message","phase":"qa","role":"user","name":"zooms","time":"2026-08-06 09:10","content":"常数和速率还是有点分不清"}
{"type":"message","phase":"qa","role":"tutor","name":"颜回","content":"记住一句话：常数只认识平衡，速率才看时间！"}
{"type":"message","phase":"teaching","role":"user","name":"zooms","time":"2026-08-06 20:00","content":"开始吧！"}
{"type":"tool_call","role":"assistant","name":"颜回","time":"…","tool_calls":[…],"reasoning":"…"}
{"type":"tool","tool_call_id":"…","name":"颜回","time":"…","path":"TEXTBOOK/讲义.md","offset":12,"limit":200}
{"type":"message","phase":"social","role":"tutor","name":"子路","auto":true,"content":"话说他今天那个追问挺厉害的"}
```

- `meta`：lesson 课次号 / date 本课完成日期（创建预填，课后结算改写实际完成日；会话列表时间位来源）/ tutor 本课导师 / status = idle 已建未开课（交流期）· ongoing 上课中 · ended 已完成（改写后立即创建下一课文件）
- `message`：phase = teaching 上课 · social 课后群聊与讨论 · qa 交流期问答；name = 发言者（用户为称呼）；content 支持 Markdown 与 LaTeX；`time` 仅用户消息携带（写入时刻，渲染排序的时间锚点）；`auto` 仅课后自动生成的群聊消息携带（UI 渲染忽略）
- `tool_call`：agent 翻书中间轮（tool_calls 原样 + 可选 reasoning 思考链，供后续请求回传）；不渲染
- `tool`：翻书结果——read 存指针（path/offset/limit，重放时物化读盘）、search 存 content 快照（关键词搜索结果，重放直接用）；失败存错误文本快照；旧格式 file/section 兼容；渲染为「📖 …」系统行
- 课次区间四段 = 交流（qa，写最新文件头）+ 教学 + 群聊（auto）+ 群聊讨论（social，写上一课文件尾）
- 文件创建：懒建——首条消息发送或「开始上课」时（见 [tab_chat.md](tab_chat.md)）；每条消息实时追加（先写后说）
