Banner 左对齐一个返回按钮，居中显示课程名。返回按钮返回聊天页。

页面主体显示课程运行状态（对应原系统 DATA/STATE.md 的「学习」区）：当前讲授位置、下一节课授课导师（每课后按 TUTOR_A→B→C→A 轮换推进）、累计课时、最近上课日期。

状态信息下方三个按钮：「学习进度」打开进度数据页（对应原系统 DATA/PROGRESS.md）；「进入对话」进入课程对话页；「导师群聊」进入群聊对话页。

每次进入课程对话页前，系统重新读取本页数据（STATE），确定本次授课导师与讲授位置；课后更新后本页数据随之刷新。

**数据存储**（对应原系统 DATA/STATE.md，单行 JSON，课后更新时整行重写）：

```json
{"position":"3-2 化学平衡移动","next_tutor":"芙宁娜","lessons":5,"last_date":"2026-08-04"}
```

- position：当前讲授位置（无教材模式保持为空）
- next_tutor：下一节课授课导师（每课后按 TUTOR_A→B→C→A 轮换推进）
- lessons：累计课时（每课后 +1）
- last_date：最近上课日期（每课后更新）

更新时机：课后更新完成时整行重写；课程信息页每次进入时读取本文件显示四项数据。

Banner 左对齐一个返回按钮，居中显示"学习进度"。返回按钮返回课程信息页。

Banner 下面平铺知识点进度列表（对应原系统 DATA/PROGRESS.md），按首次出现倒序排列（新知识点在前）。每个知识点占两行：第一行显示状态标记（✓ 掌握 / △ 薄弱 / ✗ 未掌握）和知识点短名；第二行显示最近一次接触日期、下次复习日期（→日期）。状态为 △/✗ 时在第二行下方额外显示错因（【】内，≤15字）。

一个知识点多次接触时存在多个状态块（原记录不可修改，每次接触在行末追加新块），页面默认显示最新状态块，点击该知识点展开全部历史状态块。

**数据存储**（对应原系统 DATA/PROGRESS.md，JSONL 格式，每行一个知识点）：

```jsonl
{"name":"氧化还原反应","records":[{"status":"✓","date":"2026-03-15","review":"2026-03-22"}]}
{"name":"化学平衡移动","records":[{"status":"△","date":"2026-03-18","review":"2026-03-21","mistake":"混淆常数与速率"},{"status":"✓","date":"2026-03-25","review":"2026-04-01"}]}
```

- name：知识点短名（2-8 字），行序即首次出现顺序；页面展示时新知识点在前
- records：状态块数组，按时间顺序只追加不修改
- status：✓ 掌握 / △ 薄弱 / ✗ 未掌握
- date：本次接触日期
- review：下次复习日期（✓+7d / △+3d / ✗+1d）
- mistake：错因（≤15字），仅 △/✗ 时存在

课后更新规则：新知识点 → 追加一行；已有知识点 → 整行重写，records 追加新状态块。（review 字段仅记录下次复习日期，系统不触发任何提醒）

Banner 左对齐返回按钮，居中显示群聊名称；群聊名称初始由导师在生成群聊时指定，之后用户可点击群聊名称进行修改，导师在群聊互动中也可修改；右对齐 ⋮ 按钮弹出菜单，包含「历史群聊」与「导师关系」：历史群聊进入历史群聊列表，导师关系进入关系页。返回按钮返回课程信息页（无论从课程信息页「导师群聊」还是课程对话页「打开群聊」进入）。

页面显示当前课程最新一期导师群聊（对应原系统 DATA/SOCIAL/ 最新文件），按行序逐条显示：发言者名 + 消息内容，导师消息左对齐，用户消息右对齐（与课程对话页统一），称呼为创建课程时用户希望导师称呼的名字；三位导师与用户以不同颜色区分。消息为课后生活化闲聊，不附加任何总结或评语。

输入框 + 发送按钮：用户发送消息参与群聊，消息追加写入群聊数据文件，随后生成导师回应——由 1~3 位导师以各自人设与群聊口吻回复，人数取决于当时的讨论度（话题热闹时多位导师参与，冷清时一两位回应），回应逐条追加写入文件。

课后更新完成后，课程对话页的「发送」按钮变为「打开群聊」按钮，点击进入本页。

**数据存储**（对应原系统 DATA/SOCIAL/ 最新文件，JSONL 格式，与课程对话留档共用同一消息结构）：

```jsonl
{"type":"meta","lesson":2,"date":"2026-08-04","name":"导师们的茶话会"}
{"type":"message","role":"tutor","name":"芙宁娜","content":"话说他今天那个追问挺厉害的"}
{"type":"message","role":"tutor","name":"纳西妲","content":"确实，下次那个点得再讲一遍"}
{"type":"message","role":"user","name":"zooms","content":"我也觉得那道题好难"}
```

- type：meta（首行元数据）/ message（消息）
- lesson：课次（meta）
- date：日期（meta）
- name：群聊名称（meta，用户或导师修改时重写首行）/ 发言者名（message，用户为用户称呼，如 zooms）
- role：tutor / user
- content：消息内容

追加规则：生成群聊时按原系统时间约束控制节奏（首条=下课+0~10分钟、人际间隔10~40秒、同人连发3~8秒、总跨度≤10分钟），消息不存储时间戳，行序即时间顺序；用户参与群聊与导师回复均为逐条追加。

**数据存储**（对应原系统 DATA/CHAT/ 留档文件，JSONL 格式，与群聊共用同一消息结构）：

```jsonl
{"type":"meta","lesson":2,"date":"2026-08-04","tutor":"芙宁娜","status":"ongoing"}
{"type":"message","role":"user","name":"zooms","content":"氧化还原反应的实质是什么？"}
{"type":"message","role":"tutor","name":"芙宁娜","content":"先别急着定义——电子转移前后，什么发生了变化？"}
```

- type：meta（首行元数据）/ message（消息）
- lesson：课次（meta）
- date：日期（meta）
- tutor：本课授课导师（meta）
- status：ongoing 上课中 / ended 已课后更新结束（meta，课后更新完成后由 ongoing 改写为 ended）
- role：user / tutor
- name：发言者名（用户为称呼，导师为导师名）
- content：消息内容（支持 Markdown 与 LaTeX）

直写规则：每轮导师生成回复后、显示前，一次追加用户消息与导师回复两行（先写后说）；行序即时间顺序，不存储时间戳。

历史消息页列表数据：读取各课 meta 行（课次/导师/日期），按日期倒序。课程对话页进入判断：最新一课 meta 的 status 为 ongoing → 进入续上；ended 或无留档 → 空白页等待「开始上课」。
