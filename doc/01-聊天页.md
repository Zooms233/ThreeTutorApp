# 01 聊天页设计

> 会话列表（课程群聊）+ 群聊页（上课与课后闲聊同一消息流）+ 课程信息页、课程进度页、关系页。

## 界面视图

```
[聊天页=会话列表] ⇄ [通讯录页] ⇄ [设置页]      底部 Tab 互切，默认「聊天」
   │
   └ 点击会话行 → [群聊页]
   │               └ 右上 [统计图标] → [课程详情页]（状态四项 + 知识点进度）
   │                                 └ [和导师的关系] → [关系页]（返回课程详情页）
   └ 右上角齿轮菜单 → 更名 / 删除课程（删除红字二次确认）
```

[通讯录页] → 点击导师行 → [导师资料页]
                              ├ [导师资料] → [导师档案详情页]（返回导师资料页）
                              ├ [创建群聊] → [创建课程表单] → 完成后进入 [群聊页]
                              └ 点击课程行 → [群聊页]

[设置页]：底部 Tab 直达


Banner：左对齐软件名 TutorChat；无右上按钮（创建课程入口统一在通讯录导师资料页）。

会话列表：每行一个课程群聊，微信会话样式：群名 + 最后一条消息预览（单行截断）+ 最近时间。按最后活动倒序（最后一条消息的 time；无消息用 meta.date 兑底）。最后一条消息跨文件从后往前找（讨论写在上一课文件尾，最新消息可能在倒数第二个文件）；从群聊页返回即刷新列表。点击行进入群聊页；更名/删除课程入口在 AppBar 齿轮菜单（PopupMenu：更名弹重命名对话框，群名 = 课程名 = 课程目录名；删除先选课程再红字二次确认，删除整个课程目录）。

会话数据：扫描「课程/」目录下全部课程；每课程读取最新 CHAT 文件——meta 行提供课次与日期，文件最后一条 message 做预览；课程无 CHAT 文件时预览显示「尚未开始上课」，时间位留空。

空状态：居中图标 + 文案「前往通讯录，选择导师创建群聊」。

## 群聊页（课程对话与课后闲聊同一页）

```
--------------------------------
| ‹  化学入门               ⋮  |
|--------------------------------|
| --- 第 2 课 · 芙宁娜 ---       |
|                        zooms  |
|              氧化还原反应的实质 |
| 芙宁娜                        |
|   先别急着定义——电子转移前后…  |
| --- 下课后 ---                 |
| 纳西妲                        |
|   话说他今天那个追问挺厉害的    |
|                               |
|--------------------------------|
| 输入框                    发送 |
|--------------------------------|
```

Banner：左对齐返回按钮（返回聊天页）；居中显示群名（= 课程名）。生成中状态由服务层静态 busy 表持有（跨页面、跨实例存活）：退出再进入仍显示并锁输入，生成结束后从文件重载新内容；右对齐依次为课后交流切换按钮（仅最新课次 idle 且上过课时显示，见「消息流向」）与统计图标按钮（Icons.query_stats，点击进入课程详情页）。

消息流：全部课次连续显示（含课后闲聊）。物理行序即文件内时间序；渲染时按用户消息时间戳做块级稳定排序（键 = user 自身 time；tutor 继承其前最近 user；meta 锚定其文件内首条 user；同键保持物理行序）——仅在跨文件交界（问答写下一课文件头、讨论写上一课文件尾交错使用）修正时序。

- 课次分隔行：`第 N 课 · 导师名`（渲染于本文件首条 phase=teaching 消息之前；无日期——文件跨度可跨多天；仅 UI 装饰）
- 日期分隔行：`M月D日`（渲染于时间戳发生跨日的用户消息之前；仅 UI 装饰——用户消息带时间戳，导师消息归属最近的时间锚点）
- 课后分隔行：`下课后`（渲染于本文件首条 phase=social 消息之前；仅 UI 装饰）
- 课后区（phase=social / qa）：课后更新自动生成的导师群聊 + 用户切换参与的讨论 + 问答，同一区混排；问答回应者为 next_tutor 一对一，群聊讨论由三位导师依话题选人，靠发言者名自然区分，不加额外分隔
- 文件头交流段（idle 期写入的问答）：不加分隔行；仅第 1 课文件在消息流最前显示 `你加入了群聊，现在可以开始聊天了`
- 分隔行统一为两侧细线 + 居中灰色小字样式（示意图中的 --- 仅为文案示意）
- 消息条目：微信群聊样式——导师消息左对齐（发言者名 + 内容），用户消息右对齐（显示称呼）；支持 Markdown 与 LaTeX（`$...$` 行内、`$$...$$` 独立行）

上课控制（课程详情页 AppBar 右上角按钮，不设在群聊页——远离对话区避免误触；文本路由取消，输入框仅承担对话发送）：

- 最新课次文件 idle（已建未开课）或 ended：按钮显示「开始上课」；点击触发课前准备——读 STATE 确定当日授课导师、meta 改写 idle→ongoing、当日导师以人设打招呼并宣布今天的学习内容；触发后自动返回群聊页看生成过程
- 最新课次文件 ongoing（上课中）：按钮显示「今天就到这里」；点击触发下课总结——导师以人设总结、留悬念、告别；触发后自动返回群聊页
- 下课总结完成后自动执行课后更新（后台执行）：输入框与发送按钮禁用；详情页按钮在**课程生成中全程禁用**（灰色「正在处理中…」，避免并发操作状态机），下课流程（总结→更新→群聊）完成后 meta 已改写 ended，按钮自动恢复「开始上课」
- 课后更新完成（meta 改写 ended、下一课文件创建 idle）：输入框恢复可用——进入课后交流时段（见下「消息流向」）

消息流向（输入框发送去向，由最新课次文件 status 与课后交流切换按钮共同决定）：

- 上课中（ongoing）：发送为上课对话（phase=teaching）；切换按钮不显示
- 交流期（idle）：appbar 切换按钮决定流向，且决定**写入目标文件**——未激活（默认）为**问答**（phase=qa，由 STATE.next_tutor 一对一回应，可参考教材），写入最新课次文件（下一课区间的交流段）；激活为**群聊讨论**（phase=social，三位导师依话题选人回应），写入上一课文件尾（群聊之后，紧接讨论）。问答为交流期高频动作，群聊讨论为偶尔参与，故默认不激活
- 切换状态仅会话内存（app 重启恢复默认不激活），不落盘

LLM 生成期间：输入框即状态位——hint 替换为「<导师名> 正在输入中…」（群聊阶段为「群里正在输入中…」）并禁用（微信同款，替代顶部 Banner），生成完成恢复提示语并解锁；聊天页会话列表（tab_chat）同步在预览位置显示绿色小字同文案。

每条消息实时写入当日 CHAT 文件（JSONL 逐条追加，先写后说）。

输入交互：Enter 换行（输入框 1~6 行自适应，超过内部滚动），桌面端与移动端一致，靠发送按钮发送。

## 课程详情页（群聊页右上统计图标进入）

```
--------------------------------
| ‹  课程详情        [开始上课]   |
|--------------------------------|
| 当前讲授位置  3-2 化学平衡移动  |
| 下一节课授课导师  芙宁娜        |
| 累计课时  5                    |
| 最近上课日期  2026-08-04       |
|                               |
| [和导师的关系]              ›  |
|--------------------------------|
| ✓ 氧化还原反应                 |
|    最近 03-15 → 复习 03-22     |
| △ 化学平衡移动                 |
|    最近 03-18 → 复习 03-21     |
|    【混淆常数与速率】           |
| ✗ 电化学计算                   |
|--------------------------------|
```

Banner 左对齐返回按钮（返回群聊页），居中显示「课程详情」，右上角上课控制按钮（状态机见群聊页「上课控制」节）。

- 顶部状态四项：当前讲授位置、下一节课授课导师（每课后按 tutor_a→b→c 轮换推进）、累计课时、最近上课日期；每次进入读取 STATE
- 「和导师的关系」入口 → 关系页
- 主体为知识点进度（见下）
- 更名与删除课程在聊天页 AppBar 齿轮菜单（不再放详情页）

**数据存储**（对应原系统 DATA/STATE.md，单行 JSON，课后更新时整行重写）：

```json
{"position":"3-2 化学平衡移动","next_tutor":"芙宁娜","lessons":5,"last_date":"2026-08-04"}
```

- position：当前讲授位置（无教材模式保持为空）
- next_tutor：下一节课授课导师（每课后按 tutor_a→b→c 轮换推进）
- lessons：累计课时（每课后 +1）
- last_date：最近上课日期（每课后更新）

#### 知识点进度（课程详情页主体）

平铺知识点进度列表，按首次出现倒序排列（新知识点在前）。每个知识点占两行：第一行显示状态标记（✓ 掌握 / △ 薄弱 / ✗ 未掌握）和知识点短名；第二行显示最近一次接触日期、下次复习日期（→日期）。状态为 △/✗ 时在第二行下方额外显示错因（【】内，≤15 字）。


**数据存储**（对应原系统 DATA/PROGRESS.md，JSONL 格式，每行一个知识点）：

```jsonl
{"name":"氧化还原反应","records":[{"status":"✓","date":"2026-03-15","review":"2026-03-22"}]}
{"name":"化学平衡移动","records":[{"status":"△","date":"2026-03-18","review":"2026-03-21","mistake":"混淆常数与速率"},{"status":"✓","date":"2026-03-25","review":"2026-04-01"}]}
```

- name：知识点短名（2-8 字），行序即首次出现顺序；页面展示时新知识点在前
- records：状态块数组，按时间顺序只追加不修改
- status：✓ 掌握 / △ 薄弱 / ✗ 未掌握
- date：本次接触日期
- review：下次复习日期（✓+7d / △+3d / ✗+1d）
- mistake：错因（≤15 字），仅 △/✗ 时存在

课后更新规则：新知识点 → 追加一行；已有知识点 → 整行重写，records 追加新状态块。（review 字段仅记录下次复习日期，系统不触发任何提醒）

Banner 左对齐返回按钮，居中显示标题「和学习者的关系」。返回按钮返回课程详情页。

页面展示当前课程学习者信息（LEARNER.json 的 name / motivation / extra）以及三位导师与学习者的关系：每位导师一行，显示导师名与 relation 内容（导师档案中的「与学习者的关系」字段，课程内副本课后更新后为最新版本）。

**学习者档案编辑**：学习者卡标题行右侧编辑按钮 → 对话框预填现值（称呼/学习动力必填，其他选填留空存空串）；保存只覆盖 name / motivation / extra 三键（identity / story 是世界档案固有，不可改），导师关系段不可编辑（由课后更新演进）。prompt 每次请求现读 LEARNER.json，保存后下一句话即生效。

**「从最近课次提炼」（其他字段的 LLM 辅助）**：编辑对话框内「其他」框下方的按钮——LLM 读最新课次留档全文（qa + 教学 + 群聊 + 讨论四段），按提示词 `learner_extra.md` 提炼值得长期记录的学习者特征（讲解偏好 / 学习习惯），**整段替换**「其他」输入框为草稿；只预填不落盘，用户看过/改过随「保存」写入（LLM 是助手，用户把关）。规则：无课次记录时按钮置灰；对话无可提炼特征时提示而非填入「无」；不记易错点（由知识点进度的 mistake 字段负责，避免重复）；提炼消耗入 USAGE.jsonl（scene=提炼，真实调用，非流式）。

**数据存储**：读取课程目录内 `课程/<课程名>/LEARNER.json` 的 name / motivation / extra，以及 `课程/<课程名>/tutor_a.json ~ tutor_c.json` 的 name 与 relation 字段（创建课程时从所选导师世界复制的副本，非世界目录内的静态版本）。

- 依赖：课程目录内需已有 LEARNER.json 与导师 JSON 副本（创建课程时已复制）

## 数据存储

课程目录：<存储路径>/课程/<课程名>/，内含 STATE.json、PROGRESS.jsonl、LEARNER.json、tutor_a.json ~ tutor_c.json、TEXTBOOK/（可选教材）、CHAT/。

CHAT/第N课.jsonl（一文件 = 一个课次区间：上一课结束后的交流 + 本课上课 + 群聊 + 群聊回复；文件名不带日期，跨度可跨多天；按 lesson 数值排序）：

```jsonl
{"type":"meta","lesson":2,"date":"2026-08-04","tutor":"芙宁娜","status":"idle"}
{"type":"message","phase":"qa","role":"user","name":"zooms","time":"2026-08-06 09:10","content":"常数和速率还是有点分不清"}
{"type":"message","phase":"qa","role":"tutor","name":"芙宁娜","content":"记住一句话：常数只认识平衡，速率才看时间！"}
{"type":"message","phase":"teaching","role":"user","name":"zooms","time":"2026-08-06 20:00","content":"开始吧！"}
{"type":"message","phase":"teaching","role":"tutor","name":"芙宁娜","content":"先别急着定义——电子转移前后，什么发生了变化？"}
{"type":"message","phase":"social","role":"tutor","name":"纳西妲","auto":true,"content":"话说他今天那个追问挺厉害的"}
{"type":"message","phase":"social","role":"user","name":"zooms","time":"2026-08-06 21:35","content":"我也觉得那道题好难"}
```

- type：meta（首行元数据）/ message（消息）
- meta：lesson 课次号、date 本课完成日期（创建时为预填，课后更新时改写为实际完成日；热力图统计源）、tutor 本课导师（创建时预填 STATE.next_tutor）、status：idle 已建未开课（交流期）/ ongoing 上课中 / ended 已完成课后更新（瞬时态——改写后立即创建下一课文件）
- 文件创建时机：createCourse 时（第 1 课）；课后更新流程尾（群聊落档后，下一课，status=idle）
- message.phase：teaching 上课对话 / social 课后群聊（课后更新自动生成的导师群聊写本课文件尾，用户 toggle 激活参与的讨论亦写入同一位置）/ qa 课后问答（回应者为 next_tutor，写入最新课次文件的头部交流段）
- role：user / tutor；name：发言者名（用户为称呼，导师为导师名）；content：消息内容（支持 Markdown 与 LaTeX）
- time：仅用户消息携带（`YYYY-MM-DD HH:mm` 写入时刻；导师消息不带）——用户不一定一天内上完一节课，跨天交流由此区分；渲染排序的时间锚点
- auto：仅课后更新自动生成的群聊消息携带 true——群聊总在本课文件尾，qa 的写入目标（下一课文件）天然不含群聊，无需过滤；social/teaching 照常带入；UI 渲染忽略
- 行序即文件内时间序；课次区间四段 = 交流（qa，若有）+ 教学 + 群聊（auto）+ 群聊讨论（social，若有）——qa 写最新课次文件头，讨论写上一课文件尾，交错使用时渲染按用户消息时间戳归序（见群聊页「消息流」）

直写规则：每轮导师生成回复后、显示前，一次追加用户消息与导师回复两行（先写后说）。

## 取消的页面与入口

- 课程对话页、群聊对话页、历史消息页：统一并入群聊页（连续消息流上滑即历史）
- 课程信息页与课程进度页：并入课程详情页（状态四项 + 知识点进度 + 关系入口）
- 群聊页 ⋮ 菜单：右上角改为统计图标直达课程详情页；更名/删除课程移至聊天页 AppBar 齿轮菜单
- 聊天页「+」创建课程菜单：创建入口统一到通讯录导师资料页
- 课后更新完成后的「打开群聊」按钮：不再需要（本就在群里，输入框恢复可用即代表可闲聊）
