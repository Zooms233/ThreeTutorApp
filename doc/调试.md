## 常驻调试手段

| 手段 | 位置 | 说明 |
|---|---|---|
| USAGE.jsonl 账本 | 数据根目录 | 每次成功 LLM 调用一行（time/course/lesson/scene/input/output/cacheRead/reasoning）。排查「某场景是否发出、是否成功」的第一入口：失败请求不入账 |
| stdout 用量行 | 调试控制台 | `LlmClient._logUsage` 每次调用打一行：入=命中+写入、出（含思考）、命中率、耗时，及实例累计 |
| busy 静态表 | `ThreeTutorService._busy` | 跨页面共享的生成中状态（课程名 → 文案）。退出重进聊天页仍能看到进行中状态；卡在非空即有请求未返回 |
| 兜底 toast | 群聊页 `_handleLessonAction` / `_sendMessage` | 非 LlmException 异常也会 toast 显示（不再静默失败），并注明重试方式 |

## USAGE 账本（USAGE.jsonl）

位置：数据根（与 CONFIG.json 同级），逐行 JSON 追加写；对话档案（CHAT/）不掺账目数据。

```json
{"time":"2026-02-11T20:31:05","course":"细胞生物学","lesson":"第3课.jsonl","scene":"上课","input":320,"output":1500,"cacheRead":1792,"reasoning":0}
```

- 写入点：service 层统一对话出口（上课/问候/问答/闲聊/更新/群聊/提炼，共七场景）透传后取 `result.usage` 入账，fire-and-forget 不阻塞主流程，写账失败静默；失败重试的中间请求拿不到 usage，无法入账——**账本只记成功请求**；ping 检验不计
- lesson = 课次留档文件名（无课次上下文为 null）；input = 未命中（计费且写入缓存）、cacheRead = 命中（约 1/10 计价）、output = completion_tokens

## messages 拼接跟踪（trace，临时代码）

**用途**：验证发给 LLM 的 messages 拼接是否正确——每轮实际发送前打印结构快照（角色序列 + 简化标签，不含全文）。配合 agent 翻书（read / search）可观察：翻书轮次是否追加了 `assistant(tool_calls)` + `tool(教材)` 消息、下一轮是否完整重放、各场景 system 组合差异。

**位置**：`ThreeTutorService._traceMessages()`，在统一出口 `_chatLogged` 发请求前调用；开关 `static const _traceEnabled = kDebugMode`（仅 debug 构建生效，release 编译期剔除——对话片段不落生产包 logcat；临时排查 release 问题可临时改回 true）。

**输出示例**（stdout `[trace]`）：

```
[trace] 上课#1 带工具 4条
  [0] system（teaching.md：教学规则+导师档案[苏格拉底]+学习者+状态+进度+教学范围+日期+目录（3421字））
  [1] 用户消息1「熵增原理是什么来着？」
  [2] assistant（翻书:read TEXTBOOK/讲义.md 第12行起200行）
  [3] tool（教材，2876字）
```

说明：

- system 由 `_describeSystem` 识别规则文件（teaching/qa/social/group/update/learner_extra）+ 拼装块，可对比不同场景组合差异
- 用户消息按单次请求内出现顺序编号，历史重放后编号自然连续（能看出追加）
- `带工具/不带工具` 标志可验证「末轮强制不带工具」逻辑
- **验证完可删除该方法**（临时代码，不参与正式调试）；开关已绑 kDebugMode，忘关也不会进 release 包
