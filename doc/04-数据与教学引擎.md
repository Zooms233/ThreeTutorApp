# 04 数据与教学引擎设计

> 数据存储规划（目录结构/打包/导入）+ 教学引擎架构。

## 数据存储规划

所有数据存放于应用专属目录（Android/data/<包名>/files/，无需存储权限），分为「导师世界」与「课程」两类目录。另外根目录 `CONFIG.json` 保存设置页的用户名与 API 配置（username、apiUrl、apiKey、model）。

导师世界（每世界一个目录：<存储路径>/世界/<世界名>/）：
- LEARNER.json          学习者档案（身份/称呼/学习动力/其他内容/故事背景）
- TUTOR/tutor_a.json ~ tutor_c.json   三位导师档案（固定文件名，每导师一个 JSON 整写，导师名在 JSON 内 name 字段；扫描 TUTOR/ 目录即可枚举导师，便于导师轮换）

课程（每课程一个目录：<存储路径>/课程/<课程名>/）：
- STATE.json            课程运行状态（单行 JSON，整行重写）
- PROGRESS.jsonl        知识点进度（每行一个知识点，records 只追加）
- LEARNER.json          学习者档案（创建课程时从所选导师世界复制，identity 随文件继承；再填写称呼/学习动力/其他内容）
- TUTOR/tutor_a.json ~ tutor_c.json   三位导师档案（创建课程时从所选导师世界复制）
- CHAT/YYYY-MM-DD-第N课.jsonl   课程对话留档（先写后说，逐条追加）
- SOCIAL/YYYY-MM-DD-第N课.jsonl 导师群聊（逐条追加）
- TEXTBOOK/             教材文件

创建课程时从所选导师世界复制 LEARNER.json 与 TUTOR/ 到课程目录（对应原系统初始化时从 OWN 载入导师组）。

### 初始内置导师组

应用随包内置 3 个导师世界，首次启动时自动写入「世界/」目录，之后与用户自建的导师组行为完全一致（可重命名、可删除）：

- 内置世界：教令院（原 Genshin）、星光咖啡馆（原 Café Stella）、秀知院研究所（原 Shuchi'in Academy），由原系统 OWN/ 下已建立的 md 档案转换整理为 JSON 格式；Losing Heroines、wata-nare 暂不内置
- 资源位置：assets/worlds/<世界名>/（LEARNER.json + TUTOR/tutor_a.json ~ tutor_c.json），随 APK 分发，仅首次写入，之后不再读取
- 打包经验（重要）：Flutter 3.x 的 assets 目录声明**不递归子目录**（实测 Flutter 3.41）——声明 `assets/worlds/` 只包含该目录直接文件，子目录（教令院/、TUTOR/）里的文件不会被打包，`rootBundle.loadString` 会因此抛异常；必须**逐层声明所有含文件的目录**，当前 pubspec 写法为 6 行：assets/worlds/教令院/、assets/worlds/教令院/TUTOR/、assets/worlds/星光咖啡馆/、assets/worlds/星光咖啡馆/TUTOR/、assets/worlds/秀知院研究所/、assets/worlds/秀知院研究所/TUTOR/；新增内置世界或新增文件层级时，pubspec 需同步补充对应目录声明
- 打包方式：内置资源作为应用 assets 随 APK 分发，仅首次写入，之后不再读取
- 导入方式：当前阶段（LLM 接入前）不自动复制，由通讯录 + 菜单「导入内置导师」按钮手动一次性导入（从 assets/worlds/ 复制到「世界/」，已存在的世界跳过不覆盖）；最终方案为首次启动自动复制：检测「世界/」目录为空 → 将内置导师组复制到「世界/」；目录非空则跳过（不覆盖用户数据）
- 学习者档案：内置 LEARNER.json 的 name/motivation/extra 留空（称呼、学习动力、其他内容在创建课程时填写），identity 与 story 保留（身份与故事背景来自导师世界）

## 教学引擎架构

APP 内实现本地教学引擎（agent 运行时），LLM 仅承担对话生成，教学逻辑与数据全部本地：

引擎组成：
- 指令集：教学规范（苏格拉底教学法、角色扮演、反调情规则、直写规范）编译为 APP 内置资源文件，随版本更新，不留外部导入接口
- 状态机：IDLE（等待开始上课）→ 上课中（TEACHING）→ 下课总结 → 课后更新 → 课后完成态
- 工具集：STATE/PROGRESS/CHAT/SOCIAL/TUTOR 等文件的读写方法（JSONL 逐条追加、JSON 整写/整行重写）

状态机各阶段：
- IDLE：对话页空白，输入框可用（等待输入「开始上课」）
- TEACHING：正常收发消息；输入「今天就到这」进入下课总结
- 下课总结：导师总结告别，完成后自动进入课后更新
- 课后更新：输入框与发送按钮保持禁用；自动更新 STATE/PROGRESS、生成群聊、更新导师关系；完成后「发送」按钮变为「打开群聊」（输入框保持禁用）
- 课后完成态：界面显示完整对话，输入框禁用，「发送」按钮变为「打开群聊」；退出对话页后再次进入时，检测最新一课 meta 为 ended → 回到 IDLE

课前准备（输入「开始上课」后系统依次执行，对应原系统 STAGE_1）：
1. 读取 STATE / LEARNER / 导师档案，确定本次授课导师（Banner 显示其名）
2. 读取 STATE 讲授位置，定位教材对应章节（无教材模式跳过；教材文件位于课程 TEXTBOOK/ 目录）
3. 创建当日留档：CHAT/YYYY-MM-DD-第N课.jsonl（N = 累计课时 + 1，自动计算），写入 meta 行（lesson/date/tutor/status=ongoing）
4. 导师以人设打招呼并宣布今天的学习内容

提示词文件（编译为 APP 内置资源，随版本更新；内容来源于原系统 skill 文件）：

源文件位于原 TutorChat 工作区（VS Code 版项目根）的 `.agents/skills/` 目录，本机路径：`E:\VScode\02Area\TutorChat\.agents\skills`；仅作为提示词资源来源参考，开发时按需读取，不随 APP 分发、不拷贝进 APP 项目。

- 主教学提示词：苏格拉底教学法（禁止直接讲授/问题层级/引导而非纠正/确认理解/一次一问/教学节奏）+ 角色扮演（人设/斜体旁白/第四面墙/执行静默）+ 反调情规则（委婉提醒→严肃批评→冷淡疏远）+ 直写规范
  —— 来源：.agents/skills/tutorchat/SKILL.md + STAGE_1.md 教学过程部分
- 下课总结提示词：总结逻辑链/悬念铺垫/告别/提醒
  —— 来源：STAGE_2.md
- 课后更新提示词：更新 STATE/PROGRESS（含错因提取）、生成群聊、更新导师关系
  —— 来源：STAGE_3.md + PROGRESS_SPEC.md
- 群聊生成提示词：时间约束（首条=下课+0~10分钟/间隔10~40秒/连发3~8秒/总跨度≤10分钟）、发言模式（1~3人随讨论度）、内容混合（生活≥50%）、人设一致性、反应校准、反模式
  —— 来源：SOCIAL_SPEC.md
- 导师创建提示词：角色改编要点/说话风格提取/元信息隔离/禁止项
  —— 来源：tutor-creator/SKILL.md

加载时机（引擎按状态机阶段组装）：
- 上课中：主教学提示词 + 授课导师档案 + 学习者档案 + 教材上下文 + 留档历史
- 下课总结：下课总结提示词 + 本课留档
- 课后更新：课后更新提示词 + 本课留档 + 导师档案
- 群聊互动：群聊生成提示词 + 群聊文件历史 + 导师档案
- 创建导师世界：导师创建提示词 + 用户输入的角色名

表情库（EXPRESSIONS.md）：颜文字系统已确认不在 APP 实现，无需迁移。

LLM 接入：
- 由设置页「API 配置」提供 API URL / API Key / Model，统一 OpenAI 兼容协议
- 流式输出：生成期间 UI 显示「对方正在输入中…」

每轮消息流程（先写后说）：
1. 引擎读取状态并组装提示词（教学规范 + 导师档案 + 学习配置 + 教材上下文 + 到期复习唤醒）
2. 调用 LLM 流式生成回复
