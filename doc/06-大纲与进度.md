# 06 大纲与教学进度

> 大纲即进度文件。二态 checkbox（`[ ]` 待学 / `[x]` 已学），无独立 position 存储，无编号系统，无 `[-]` 中间态。LLM 职责收敛为两件事：教学（对话本身）、报告（照抄原子行 + 判定学完）；一切进度推演、寻址、校验、写入均为 app 确定性逻辑。

## 背景与教训（2026-09-16 遗传学事故）

教学延伸使实际学习轨迹呈"跳跃式覆盖"（第 1 课从绪论一路延伸到第五章连锁），而 position 是单个由 LLM 自由生成的标签。事故链四个失效环节：

1. **写入无校验**：课后更新 LLM 编造大纲中不存在的位置（"3-1 基因连锁与交换定律"——大纲无编号、无此节名），`_applyLessonUpdate` 照单全收
2. **解析静默降级**：`_resolvePosition` 只匹配 `#` 标题行，position 必然落空 → 教材注入退化为纯目录，失效信号被吞
3. **注入无未学信号**：进度证据只剩 position 字符串 + 知识点清单，"清单里有 = 学过"成为导师唯一可行推理（第 2 课玻尔 reasoning 实锤），第 3 课导师面对学习者质疑仍坚持没跑偏
4. **模型层错配**：单标签书签隐含"此前皆已学"，无法表达覆盖矩阵——"哪些章未系统学"无处存放

**根治思路：进度与大纲合体，消灭独立的 position 存储本身。** 事故的每个环节在结构上不再可能，而非靠规则防范。

## 数据模型

### 大纲格式（`OUTLINE/*.txt`）

```markdown
# 第五章 连锁遗传和性连锁

## 连锁基因的交换和重组型配子

- [x] 完全连锁与不完全连锁
- [x] 交换与重组

## 交换值测定、基因定位与连锁图

- [ ] 重组率
- [ ] 两点测验
```

三条结构约定，全部由校验器强制：

1. **标题两级**：`#` 章、`##` 节；原子行 `- [ ]` 必须在节内
2. **二态 checkbox**：仅 `[ ]` / `[x]`。原子化后不存在"部分完成"——`[-]` 的存在理由（单行装多个知识点、需表达行内进度）被拆行消灭
3. **文本全文唯一**：节标题、原子行文本均不得跨文件重复（跨节重复如裸"应用"由生成端带限定语解决）

- **原子粒度标准**：一行 = 一个可独立检验的知识点（心算可完成的小题能检验）——与 teaching.md「小题检验：每推进一小步出一道题」的推进单位对齐。三个粒度由此统一：教学推进单位 = 大纲状态单位 = PROGRESS 登记单位
- **标题里的"第N章"是教材内容**（来自教学日历），不是寻址机制的一部分，不做任何约束

### 语义分工（正交，缺一不可）

| 机制 | 语义 | 回答的问题 |
|---|---|---|
| 大纲 checkbox | 覆盖 | 教过没有 |
| PROGRESS.jsonl | 掌握度 | 学会没有（✓△✗ + 错因 + 复习调度） |

延伸学习（课内跳纲触达）只进 PROGRESS，**不动 checkbox**——正式学到该行时以检验快速通过、不当新知识重讲。覆盖完整性由 checkbox 保证，个性化由 PROGRESS 保证。

### STATE.position 退役

- 当前节 = 第一个含 `[ ]` 的节；当前知识点 = 该节第一个 `[ ]`——纯派生，任何时刻自明
- STATE 保留 `next_tutor` / `lessons` / `last_date`
- 无编号的理由：编号的四项职责在方案演进中全部消失——稳定主键（position 存储已不存在，引用只在单次请求生命周期内）、LLM 生成约束（改为照抄原文）、排序（行序即顺序）、寻址（文本前缀匹配）。去掉编号反而消除：手动插节重排号、合并时的编号映射、校验器编号连续性规则
- **迁移外部完成，代码不写迁移逻辑**；代码假定新格式，不合规格被校验器拦截在入口（这是"代码只认新格式"成立的前提）

## 运行时流程

### 课前：程序化 dispatch（LLM 零推演）

app 扫大纲 → 第一个 `[ ]` → 生成确定性调度指令："今天学习《节名》的「原子行」"。LLM 收到的是指令，不做进度判断。全 `[x]` 时走结课分支。

### 课中

- 课中随时中断/恢复 = 同一课文件、`_mapHistory` 自然重放，**无任何额外处理**（伪场景"课中离开未结算"不存在——没点"今天就到这里"课就没结束）
- 大纲全文随 system 注入（现状机制），checkbox 状态对 LLM 可见
- 延伸自由：触达的知识点课后进 PROGRESS，checkbox 不动

### 课后结算：唯一写点（点击「今天就到这里」触发）

1. update 请求**注入大纲全文**（现状不含）——判定"学完"需对照每节要点清单
2. LLM 输出（update.md 新 schema）：`sections_done`（本课教过的原子行，**照抄注入清单原文**）+ `progress` + `relation`；`position` 字段删除
3. app 校验：逐条"节标题 + 行文本前缀"匹配 → 行状态必须为 `[ ]` → **全部通过才写文件**（标 `[x]`）；失败打回重试（沿用现有 2 次循环，重试消息附失败原因），文件不动
4. 学完判定标准写进 update.md：要点覆盖 + 小题检验通过；宁保守不冒进，教过一半不算
5. **无推进写入、无连续性校验**——乱序合法（跳章是学习者的自主权），跳纲已由 checkbox 显式化，不再是事故。插队学完后焦点自然回归主线（第一个 `[ ]`）
6. 照抄原文而非默写行名：匹配模糊性由此消除；写明理由——update 请求本就注入了带 checkbox 的大纲

### 跨课：开课首轮载入上一课教学段

新开课文件只含 qa 交流段，上一课教学对话不在历史里 → 开课首轮映射上一课文件教学段，LLM 依据（大纲 checkbox = 学过什么 + 上节课对话 = 聊到哪）接续话题。全量或截尾为实现期决策。与"课中中断"划界：后者不需要任何机制。

## 格式校验器（入口硬拦截）

建课/导入大纲时执行，不合规则**拒绝导入**，报错精确到行号：

- 标题层级合法（`#` 章 / `##` 节两级，原子行必须在节内）
- checkbox 语法合法（仅 `[ ]` / `[x]`，无 `[-]`）
- 节标题全文唯一、原子行文本全文唯一

定位：不是友好提示，是新方案成立的前提——一份不合规格的大纲导入后解析器瞎掉、静默降级，即第 1 课事故的教训重演。

## 导入：覆盖为主，合并外置

- **导入（app 内唯一入口语义）**：新大纲整文件替换旧大纲，导入前过校验器，不合格拒绝并报行号。替换即进度重置（新大纲全 `[ ]`），UI 警示"覆盖将丢失学习进度"
- **合并（软件外部实现）**：结构变化时（教学日历更新、章节调整），用户在外部网页对话中完成旧大纲 → 新大纲的标记迁移，app 不内置合并调用——省本地调用成本，产物经复制粘贴走正常导入 + 校验器拦截。为支撑外部操作，合并提示词（迁移规则：结构以新为准、同名/同义条目继承状态、无对应进度丢弃并列冲突清单）作为资产在设置页暴露，与大纲生成提示词并列

## 提示词资产变更

| 资产 | 变更 | 归属 |
|---|---|---|
| `outline_gen.md`（新增） | 大纲生成：格式约定、原子粒度标准、文本唯一性提醒（要点名冲突带限定语）、实验章/自学注记处理 | 设置页查看/复制，供外部模型使用 |
| `update.md`（重写） | 删 position；新增 sections_done 照抄规则 + 学完判定标准 | 内置 |
| `outline_merge.md`（新增） | 迁移规则、冲突清单格式——**供外部网页对话使用**，app 不内置合并调用 | 设置页查看/复制，与大纲生成提示词并列 |
| `teaching.md`（微调） | 补一条：延伸接触过的知识点，正式学到时以检验快速通过，不当新知识重讲 | 内置 |
| `dispatch_greeting.md`（微调） | 学习内容由 dispatch 指令指定（app 拼入节名/原子行），不再"按大纲宣布"由 LLM 自行决定 | 内置 |
