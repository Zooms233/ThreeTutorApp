# 教学过程

> 一门课程从开课到结课的完整生命周期。核心机制：**大纲即进度文件**——无独立进度存储，指针是派生视图；**LLM 只管教学对话与照抄报告，推演/校验/写入全是 app 确定性逻辑**。

## 生命周期总览

```
 建课（表单 + 大纲导入，校验拦截不合格）                    [app]
   ↓
 课前「开始上课」：开新课次档案（idle）→ 课前问候          [app 建档 → LLM]
    宣布今天学习《节》的「知识点」（dispatch 程序化）
   ↓
 课中：按大纲逐行推进（一行 = 引入 → 小题检验）            [LLM 对话]
    延伸自由、收束回主线；随时中断 = 同一课文件自然续
   ↓
 课后「今天就到这里」：结算                                [LLM 报告 → app 校验写入]
    LLM 报学完清单（照抄 + 证据）→ app 双闸门 → 标 [x]
   ↓
 群聊生成 → 下一课文件创建（idle 预填）                    [LLM 群聊 → app 建档]
   ↓
 ……指针随每次结算自动前进……
   ↓
 全 [x] → 结课态（dispatch 走商定分支，清单页显示结课）
```

## 设计原则

| 原则 | 内容 |
|---|---|
| 派生而非存储 | 当前知识点 = 大纲中从上到下第一个 `[ ]`，即时计算，无独立进度存储 |
| 单一写点 | 勾选只发生在课后结算；课中无任何写路径 |
| 校验前置 | 一切外部输入（大纲、LLM 输出）进系统前过校验器，不合格拒绝 |
| 职责收敛 | LLM：教学对话 + 结算报告（照抄+判证据）；app：推演、寻址、校验、写入 |

## 数据基础：大纲即进度文件

```markdown
# 第五章 连锁遗传和性连锁

## 连锁基因的交换和重组型配子

- [x] 完全连锁与不完全连锁
- [x] 交换与重组

## 交换值测定、基因定位与连锁图

- [ ] 重组率
```

| 结构约定（校验器强制，`service/outline.dart`） | 规则 |
|---|---|
| 标题两级 | `#` 章 / `##` 节；知识点行必须在节内 |
| 二态 | 仅 `[ ]` 待学 / `[x]` 已学；一行 = 一个可独立检验的知识点，无 `[-]` 中间态 |
| 文本全文唯一 | 节标题与知识点文本不重复——寻址靠「节标题 + 行文本前缀」，顺序靠文件行序 |

- **原子粒度**：教学推进单位、大纲状态单位、PROGRESS 登记单位三者对齐为一行
- **双账本分工**：大纲 checkbox = 覆盖（教过没有）；PROGRESS.jsonl = 掌握度（✓△✗ + 错因 + 复习调度）——任一本的局部误差由另一本提供恢复路径
- 标题里的「第N章」是教材内容，不是寻址机制的一部分

## 课前：dispatch 程序化（LLM 零推演）

```
            ┌─ 大纲存在 ────→ firstPending ─→「今天学习《节名》的「知识点」，按大纲顺序逐行推进」
「开始上课」─┼─ 全 [x] ─────→ 结课分支（商定复习 / 延伸 / 结课）
            └─ 无大纲 / 解析失败 → 纯模板（教学相长：师生共同商定方向）
```

- 问候调度指令 = 模板 `assets/prompts/dispatch_greeting.md`（「课程开始。以{导师名}的身份打招呼。……商定后开始教学。」）+ app 追加今日学习内容；结课分支追加「可复习薄弱知识点、横向延伸，或确认结课」
- 问候与上课对话同拼装（问候多调度指令），详见下「请求拼装」

## 课中：逐行推进契约（teaching.md 规则，teaching 产证据、update 验证据）

```
   ┌──→ 引入当前知识点行 → 小题检验 ── 通过 ──→ 下一行 ──┐
   │                      └─ 未通过 → 继续引导（不直接给答案）
   └────── 延伸（鼓励追问）────── 收束回主线 ←────────────┘
```

- 一行 = 一次完整「引入 → 检验」单元：不跳行、不一次铺开多行；一行一检验，通过才算走完
- 延伸触达的知识点**只进 PROGRESS（掌握度），不动 checkbox**——正式学到时检验快速通过，不当新知识重讲
- 课中随时中断/恢复 = 同一课文件自然续，无额外处理

## 课后结算：指针推进的唯一写点（「今天就到这里」触发）

```
 LLM 读完整课堂对话 + 大纲全文（清单驱动遍历：逐节为每个 [ ] 行找证据）
    ↓ 输出 JSON
 sections_done（逐字照抄大纲原文 + 每项附对话证据）/ progress / relation
    ↓ app 双闸门
 ① resolveDone：逐项定位（精确匹配 → 前缀兜底唯一命中，须为 [ ] 行）
 ② markDone：落盘前逐行重新解析核验
    ✗ 任一失败 → 打回重试（附原因，共 2 次）→ 仍失败：文件不动、meta 保持 ongoing
    ↓ 全通过
 写档六步（app 确定性执行）：
 ① STATE 重写：next_tutor 按 tutor_a→b→c 轮换；lessons+1；last_date=今日
 ② PROGRESS：新知识点追加行 / 已有行 records 追加块
    review = 今日 + 偏移（首次✓+7；连续✓ 7→14→30→60 封顶；△+3 / ✗+1 重置）
 ③ 大纲勾选：仅替换 `- [ ] ` → `- [x] `，其余字节不变
 ④ relation 有差异 → 重写本课导师档案
 ⑤ 本课 meta → ended；群聊生成写本课文件尾（失败跳过不阻塞）
 ⑥ 创建下一课文件（idle 预填；qa 交流随后写它的头部）
```

- 勾选标准**宁保守不冒进**：要点完整覆盖 + 通过对应小题才输出；讲过一半、仅提及、未通过检验的行保持 `[ ]`，后续课次补勾（PROGRESS 已有掌握度记录）
- 结算请求拼装：update.md（规则 + PROGRESS 规范）→ 现有知识点短名清单 → 大纲全文 → 本课导师档案（精简）→ 对话历史（重试附校验失败原因）
- **指针前进是派生的副产品**：`firstPending` 下次读取自动指下一行，没有谁去移动指针
- 分工原则一句话：**LLM 报告，代码落账**——LLM 无文件通路，对文件系统的全部影响就是那次 JSON

## 跨课：接续话题

```
 上一课文件（教学对话 + 群聊）──┐
                              ├─ 本课未开讲（无 teaching 轮）→ 载入作历史前缀
 本课文件（qa 交流段）────────┘   已开讲则不载入；全量载入，实测过长再截尾
```

- LLM 依据（大纲 checkbox = 学过什么 + 上节课对话 = 聊到哪）自然接续话题

## 进度呈现

- 详情页「教学进度」行：派生摘要（当前节 · 已学 n/m；结课显示已学完全部内容）→ [course_detail_page.md](chat/course_detail_page.md)
- 清单页：章/节/知识点 ✓/▢ 三层，第一个待学行高亮「进行中」作参考焦点；v1 只读（勾选由结算维护，纠正状态可外部编辑大纲文件，重进即重读）→ [syllabus_page.md](chat/syllabus_page.md)

## 大纲生命周期管理（建课前）

```
 设置页复制「大纲提示词」→ 应用外网页对话生成 → 产物粘贴回 app（主入口）/ 选文件（次入口）
   ↓ 导入即校验：不合格拒绝并展示行号错误
 覆盖 = 整文件替换（更换时校验失败旧大纲原样保留）
 手动编辑大纲文件 = 逃生门（跳章、纠错），下次任何操作过校验器兜底
```

## 边界情况

| 场景 | 行为 |
|---|---|
| 课中中断（未点下课） | 同课文件自然续，进度零丢失只是延迟落盘 |
| 跳章（学习者主动） | 外部把目标节前的行保持 `[ ]`，学完的目标行结算照常 `[x]`；指针指主线第一个缺口，乱序期间注意力由对话历史承载 |
| 一节课学不完一行 | 指针驻留（第一个 `[ ]` 不变），节内继续由上节课对话承接 |
| 末节学完 | 全 `[x]` → 结课态：dispatch 走商定分支，清单页显示结课 |
| 无大纲课程 | 全程教学相长：dispatch 无节信息、结算 sections_done 为空、详情页显示「未设置大纲」 |

## 请求拼装与缓存分层

```
┌──────────────────────────────────────┐
│ 教学规则 teaching.md                  │  ← 稳定前缀：字节级一致 = 缓存命中（约 1/10 计价）
│ 导师档案（你是{导师名}。下面是你的档案）│     稳定段内禁止插入动态数据
│ 学习者档案                            │
│ STATE（下任导师/课时/最近日期）        │
│ PROGRESS 知识点清单（到期 top3 ★）     │  ← 换导师 = 档案变 = 缓存重建（自然边界）
│ 教学范围（大纲全文，含 checkbox）      │
│ 今日日期                              │     课中大纲不变更（勾选只在结算），
│ 材料目录（OUTLINE+TEXTBOOK 行号簿）    │     教学多轮前缀稳定
├──────────────────────────────────────┤
│ 对话历史（本课未开讲时前置上一课全文）  │  ← 随对话增长
│ 调度指令（仅课前问候追加，不写档）      │  ← 动态尾部
└──────────────────────────────────────┘
```

- 课后更新与群聊生成为独立请求，不走教学缓存分层
- 失败的可见表现：问候失败 meta 保持 ongoing（直接发消息即恢复）；结算失败（闸门耗尽）meta 保持 ongoing、大纲不勾选（重新点击重跑）；群聊生成失败跳过不阻塞

## 教学过程可用工具（agent 翻书）

带工具的请求：上课对话、课前问候、问答；不带：群聊讨论（social）、群聊生成、课后更新、画像提炼。工具定义集中在 `prompt.dart`（agentToolDefs，各场景同一份，请求字节级一致以延续缓存前缀）。

| 工具 | 参数 | 行为 |
|---|---|---|
| read | path 必填（目录中相对路径）/ offset 默认 1 / limit 默认 120、最多 500 | 按行读取；8000 字符预算内保留整行（不拦腰断行）；头部标实际行区间，尾部带续读指引（未到文件尾即提示「继续读用 offset=N」） |
| search | pattern 必填（不区分大小写子串）/ path 可选（省略 = 搜全部材料） | 逐行命中返回「文件 第 N 行：内容摘要」，上限 30 条并提示缩窄；无命中返回明确提示（供换词重试） |

- 寻址依据 = system 尾部【教学材料目录】：标题行号清单，200 条超限后自动补 200 行分段块（全文可寻址；无标题文件整体按 200 行分段）；仅文本文件纳入（扩展名白名单见 [relation_page.md](chat/relation_page.md)）——PDF/Word 需先转文本，图片不入流程
- 引导的翻书姿势（写进工具描述）：先 search 定位行号 → 再 read 精读上下文
- 翻书循环：单次回复最多 4 轮，末轮强制不带工具出文本；中间轮落档 tool_call/tool 行——read 落指针（重放物化读盘）、search 落快照（重放直接用），字节级一致保证前缀缓存延续；行格式 → [group_chat_page.md](chat/group_chat_page.md)
