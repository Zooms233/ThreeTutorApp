# 04 LLM 调用设计

> 一次请求 = 读档 → 组装 → 调用 → 写档；LLM 无状态，app 每次重建完整上下文。SSE 解析与重试退避按 pi `packages/ai` 规则实现（仅取其规则不搬其代码）。

## 输出协议

对话场景（教学/问答/问候/聊天/群聊）均为流式纯文本：教学/问答/问候为整段回复落档一条；聊天/群聊每行「导师名: 内容」逐行解析落档。唯一 JSON 场景是课后更新：`response_format: json_object` 非流式，`max_tokens: 4096` 防截断 + `thinking: low` 防思考爆炸（disabled 会复读指令不执行，实测；默认 high 曾思考 6700 token / 75s）。

## 可载入资源

- 教学规则：app 常量——苏格拉底教学法（禁止直接讲授/一次一问/鼓励追问/引导不纠正/小题检验/知识串联/适度挑战）+ 节奏（学习者决定下课/宁透不赶/承前启后）+ 角色扮演（斜体旁白/颜文字/不破第四面墙/执行静默）+ 反调情（逐步升级：委婉→严肃→冷淡→恢复）
- 问答规则：app 常量——认真答疑、可翻教材；不推进教学（不出题/不借机开课），不破第四面墙；想系统学则引导走详情页按钮（开课唯一入口）
- 聊天规则：app 常量——跟随学习者话题（课程回味与生活闲聊皆自然）；不上课：不出题/不做课堂式检验/不做课程总结汇报，聊知识是朋友间的闲聊
- 导师档案：`tutor_a~c.json`——姓名/身份/性格关键词/性格与动机（压缩版）/说话风格/示例句/情绪表现/与学习者的关系；**分场景裁剪**：教学/问答全量，聊天与群聊轻量（省略性格与动机、情绪表现），课后更新精简（保性格与动机，省略风格示例与情绪）——群聊/更新为独立请求不命中缓存，裁剪直接省 token
- 学习者档案：`LEARNER.json`——称呼/动机/知识背景/故事
- STATE：`STATE.json`——当前位置/下任导师/累计课时/最近上课日期
- PROGRESS：`PROGRESS.jsonl`——知识点短名 + 最新状态块（✓△✗ / 日期 / 错因）
- 教学范围：`OUTLINE/*`（可选）——教学大纲，短，教学/问答**全文注入**（标【教学范围】）；无大纲则教学相长（师生共同商定方向），教材/材料的存在不改变这一约定
- 教学材料：`TEXTBOOK/*`（可选，可多个）——参考数据库，格式不限（识别 .md/.markdown/.txt/.text/.log 文本）；教学注入当前进度位置内容（标题匹配行范围，超 8000 字截断）+ 目录；问答仅注入目录（需要时 read 按需载入）；聊天/群聊不注入
- 对话：`CHAT/第N课.jsonl` 全部 message 行——meta 行不映射；user→user、tutor→assistant 原文原样；用户消息 time 并入 content 头部；连续 user 消息合并；全文件历史（含文件头交流段）；textbook 指针行读盘物化为 user 消息（兼容旧档）；**tool_call/tool 行**（agent 翻书中间轮）原样透传 assistant(tool_calls)、tool 指针行物化为 tool 消息（见「agent 翻书」）；auto 标记（群聊）仅 social 场景使用，qa 的写入目标文件天然不含群聊
- 调度指令：运行时拼接，追加请求尾部，不写入 CHAT（文本见下）；共两版：问候 / 群聊
- 更新指令 + PROGRESS 规范：app 常量，仅课后更新请求使用
- 群聊规范：app 常量，仅导师群聊生成使用——以课堂内容为自然锚点（回味/质疑/追问/延伸），生活闲聊调剂不占主体；评价学习者具体且有分歧，可翻课堂上没答好的点，禁止三位导师轮流一致表扬；禁止旁白星号、发言模式随机（一/二/三人，二最常见）、消息总数约 10 条
- 运行时注入（非文件）：今日日期=当天日期；课后更新请求用 max_tokens 4096 + thinking low（实测 disabled 会复读指令不执行）

载入顺序即缓存分层：稳定在前、易变靠后（规则 → 档案 → 状态 → 日期/教材 → 对话历史）。前缀字节级稳定 = 命中（约 1/10 计价）；稳定段内禁止插入动态数据；换导师 = 档案变 = 缓存重建（自然边界）。课后更新与群聊生成为独立请求，不走此分层。

## 场景与载入

- 问答：idle 期一对一答疑，next_tutor 单人直接回应，无需前缀选人——问答规则 + next_tutor 导师档案 + 学习者档案 + 教学范围（大纲，若有）+ 材料目录（仅目录）+ 对话（写入目标为最新课次文件，天然不含群聊）+ `read` 工具（按需查阅）
- 教学（ongoing）：本课导师（meta.tutor）回应——教学规则 + 本课导师档案 + 学习者档案 + STATE + PROGRESS（知识点清单：`✓ 短名（错因）`，到期项行尾打 ★待复习，≤3 条 app 按 review≤今日推导，段尾内联带出规则；无日期）+ 教学范围（大纲，若有）+ 今日日期 + 材料（当前位置内容+目录）+ 对话 + `read` 工具（按需查阅，如温习前节/预习后节）
  - 课前问候：按钮「开始上课」触发，meta idle→ongoing，请求尾部追加调度指令（问候）
  - 上课对话：用户消息驱动
- 课后更新：按钮「今天就到这里」触发（教学收尾时导师已自然总结，不再单独生成告别语——2026-09 实测），`json_object` 非流式——更新指令 + PROGRESS 规范 + PROGRESS（现有知识点清单，供沿用短名） + 本课导师档案（精简版：保性格与动机与关系，省略风格示例与情绪） + 对话
- 导师群聊生成：课后更新完成后自动执行，聊天职责的自动版，输出若干条 `{导师名}: {内容}` 流式生成、逐行落档写本课文件尾（教学对话之后，消息带 auto 标记）——群聊规范 + 三位导师档案（轻量版）+ 本课对话（含教学全程，讨论的素材库不裁剪） + 调度指令（群聊版，只管启动与格式，规范只写一遍）；群聊落档后创建下一课文件
- 聊天：idle 且 toggle 激活，回应者取决于用户消息指向的导师（点名/接话谁就谁回应），回复格式 `{导师名}: {内容}` 单条一位导师，app 解析前缀（未命中则 name 取 meta.tutor）——聊天规则 + 三位导师档案（轻量版） + 对话（写入目标为上一课文件尾，含教学全程与群聊；问答场景写入目标为最新课次文件）

## agent 翻书（按需载入教学材料）

对齐 pi agent harness：请求带通用 `read` 工具（OpenAI 兼容 `tools`，DeepSeek 原生支持）→ 响应含 `tool_calls` → app 执行（按行读取 + 截断）→ 以 `role: tool` 消息追加上下文 → 再请求，循环直到无翻书。上限 4 轮，末轮不带工具强制出文本。启用场景：问答与教学（含课前问候）；更新/群聊/聊天不带工具。

**通用 read（格式无关）**：参数 `path`（OUTLINE/ 或 TEXTBOOK/ 下相对路径）+ `offset`/`limit`（行号，1 起始），不做任何格式解析——兼容任意文本教材；行号寻址依据来自注入的【教学材料目录】（标题+起始行号清单，无标题文件按 200 行一段列块）。工具定义：`PromptBuilder.readToolDefs`；执行：`executeReadTool`。执行失败（文件不存在/行号越界/参数错）→ tool 消息返回错误文本，模型对照目录自行修正。

**思考模式约束（DeepSeek 2026-09 文档）**：带 `tools` 的请求必须完整回传历史所有轮次的 `reasoning_content`，否则 400。思考强度为设置页右上角的全局两段式配置（教学组 / 日常组各三档：无 / 低 / 高，取值 `disabled` / `low` / `high`，落盘 CONFIG.json 启动恢复；暂不支持 max）：

- **教学组**（上课对话/问答/课前问候，带翻书 tools）共用一档，默认 `disabled`。开启后响应的 `reasoning_content` 随 `tool_call`/tutor 行落档（`reasoning` 字段，只存不展示），会话内翻书循环即时回传（current 链），跨请求由历史拼装从档回传（prompt `_mapHistory` 映射为 `reasoning_content`）；旧档案无该字段（disabled 时代）不回传——未思考的轮次无内容可回传，符合约束语义。切换档位后历史混档（部分行带 reasoning 部分不带）服务端容忍度需实测
- **日常组**（群聊生成/闲聊/课后更新/画像提炼，纯文本无 tools）共用一档，默认 `low`——群聊/闲聊为人设对话思考收益低，更新曾实测 disabled 复读指令、high 思考爆炸（默认 high 曾思考 6700 token / 75s），low 为收益/成本平衡点

**落档（CHAT 只存指针不存正文，延续材料哲学）**：

- 翻书轮次落档 `tool_call` 行：`tool_calls` 数组原样（assistant 消息），重放时透传
- 工具成功落档 `tool` 行：只存 `path`/`offset`/`limit` 指针，重放时物化读盘；失败落档 `content` 错误快照，重放直接用；旧格式 `file`/`section`（read_textbook 遗留）仍兼容物化
- 首轮请求的 assistant(tool_calls)/tool 消息与重放均经 `PromptMessage.toMap()` 构造 → 键序字节一致 → 下次请求前缀命中延续（多轮翻书每轮新增量才计费）

**UI**：翻书期间 busy 文案切「{导师} 正在翻阅教材…」；`tool` 行渲染为系统提示「📖 {导师} 查阅材料：path 第 N 行起」，`tool_call` 行不渲染。成功行的「查阅材料：…」部分染链接蓝（0xFF576B95）可点，点击经 `OpenFilex.open` 调系统「打开方式」用外部应用打开材料文件（Android 经插件内置 FileProvider 转 content://，其 external-path 覆盖公共 Documents 目录；Windows 走插件 `cmd /c start` 分支）——本应用不做预览，不定位行号（行号文字仅作信息展示）；文件已移除/无关联应用时 toast 提示。

## 触发与消息流向

输入框发送的消息三态，由最新课次文件 status 与 toggle 唯一确定：

- idle 且未上过课（lessons = 0）→ 问答（此时无 toggle）
- idle 且上过课，toggle 未激活（默认）→ 问答
- idle 且上过课，toggle 激活 → 聊天
- ongoing → 教学（toggle 不显示）

toggle 显示条件：idle 且 lessons ≥ 1；默认不激活，状态仅会话内存，不落盘。通用约束：先写后说——用户消息落档后才发请求，回复落档后才解锁输入框；日期等确定性计算全部 app 完成。

消息修改重发（sendUserMessage / sendLessonMessage 的 edit 模式）：长按当前流最后一条用户消息（流判定与发送同源，teaching/qa 指最新课次文件、social 指上一课文件尾）可修改重发——不再追加新行，而是改写目标文件物理最后一条 user 行（content 与 time 更新为编辑时刻）并截断其后所有行，随后拼装生成照旧——被改行恰在本次拼装读取的文件内，回复必然衔接。安全性依据：该行之后只可能是本轮回复链（tool_call/tool/tutor），auto 群聊行要么在别的文件、要么在该行之前；生成失败时回复链可能残缺，截断后重发即恢复。UI 判定（非 busy、非修改中、物理最后一条 user 行）与执行间由 busy 锁保证无并发写档，重试幂等。

## 调度指令文本

- 问候：「（课程开始。以{导师名}的身份打招呼。若已有教材进度，宣布今天的学习内容；否则结合学习者的目标与已学内容，与 ta 共同商定今天的学习方向，商定后开始教学。）」（无教材模式为教学相长：方向由师生共同确定）
- 群聊：「（课程刚结束，你们仨在群里自然聊了起来。现在开始，直接输出群聊消息：约 10 条，每条一行「导师名: 内容」。不要解释，不要输出任何设定或说明。）」（条数格式与规范一致即可，规范内容不重复）

## 失败处理

- 三种对话职责：重试耗尽 → 输入框解锁，用户消息已留档（悬空），再发时连续合并消化
- 课前问候失败：meta 保持 ongoing，用户直接发消息即走教学上课对话
- 课后更新失败（JSON 解析重试 1 次后仍失败）：meta 保持 ongoing、下一课文件不创建，输入框恢复可用，重新点击「今天就到这里」重跑
- 导师群聊生成失败：跳过（下一课文件照常创建），不阻塞课后更新其余成果

## 课后更新写档（解析成功后按序执行，全部 app 端计算）

输出契约：

```json
{
  "position": "3-2 化学平衡移动",
  "progress": [
    { "name": "氧化还原反应", "status": "✓", "mistake": null },
    { "name": "电化学计算", "status": "△", "mistake": "混淆常数与速率" }
  ],
  "relation": "本课导师与学习者的关系段落（态度有可感变化才改，每次只前进一步；无变化则原样返回现文）"
}
```

JSON 提取：剥离 ```json 围栏 → `jsonDecode`；失败则整请求重试 1 次（组装原样重发）。

1. STATE 单行重写：position 取 LLM 输出；next_tutor 按 tutor_a→b→c 轮换推进；lessons+1；last_date=今日
2. PROGRESS：新知识点追加一行；已有知识点整行重写（records 追加新状态块）；date=今日、review=今日+偏移（自适应：连续 ✓ 递增 7→14→30→60 天，△+3 / ✗+1 重置）
3. relation 与现文有差异 → 重写本课导师档案的 relation 字段；无差异不写
4. 本课 meta 整行改写：status→ended、date→今日（实际完成日，热力图统计源；lesson/tutor 保持）
5. 导师群聊生成写档于本课文件尾（教学对话之后；失败跳过不阻塞其余成果）——流式逐行落档：每行「导师名: 内容」生成完整（遇换行）即写档并回调，UI 实时逐条弹出，不等全量聚合、无人为停顿
6. 创建下一课文件 `CHAT/第{N+1}课.jsonl`：meta 预填（lesson=N+1、tutor=轮换后导师、date=今日、status=idle）→ 全部完成后输入框恢复可用（此时 lessons ≥ 1，toggle 开始显示；qa 交流写它的头部，social 讨论写上一课文件尾）

## 协议层（client.dart）

- 请求：POST `<apiUrl>/chat/completions`（apiUrl 已含端点时防重复拼接，兕底手改 CONFIG 的场景），头 `Authorization: Bearer <apiKey>`；CONFIG 三项（apiUrl/apiKey/model）来自设置页（服务商选择仅设置页概念：DeepSeek 内置接口覆盖 apiUrl，调用层不感知）；`temperature`/`max_tokens` 用服务商默认
- 连通性检验 `ping`：设置页专用，最小请求（`max_tokens=1`，非流式，15s 超时）验证配置；返回 (成功, 描述)；不计入 usage 调试累计
- 字段：model、stream=true（仅课后更新非流式）、messages、stream_options=`{"include_usage": true}`（仅流式）、response_format=`{"type":"json_object"}`（仅课后更新）
- 本项目参数：最多 3 次尝试（408/409/429/5xx/网络异常可重试，退避按 pi 规则）；连接与响应头超时 30s；流式无新数据 120s 判死（按断流处理，已收内容丢弃进重试）
- usage 兼容链：cacheRead = `prompt_tokens_details.cached_tokens` ?? `prompt_cache_hit_tokens`（DeepSeek）?? `cached_tokens`；input = prompt_tokens − cacheRead；每次成功请求后：① stdout 调试行 `[llm 场景]`（入/命中/写入/出/命中率/耗时 + 会话累计）② 追加一行进数据根 **USAGE.jsonl 账本**（见下）。验收：课堂第 2 轮起 cacheRead ≈ system + 历史长度

### 用量账本（USAGE.jsonl）

位置：数据根（与 CONFIG.json 同级），逐行 JSON 追加写；对话档案（CHAT/）不掺账目数据。

```json
{"time":"2026-02-11T20:31:05","course":"细胞生物学","lesson":"lesson-003.jsonl","scene":"上课","input":320,"output":1500,"cacheRead":1792}
```

- 写入点：service 层统一对话出口（含「提炼」工具场景，共六场景）透传后取 `result.usage` 入账，fire-and-forget 不阻塞主流程，写账失败静默）；失败重试的中间请求拿不到 usage，无法入账——**账本只记成功请求**；ping 检验不计
- lesson = 课次留档文件名（无课次上下文为 null）；input = 未命中（计费且写入缓存）、cacheRead = 命中（约 1/10 计价）、output = completion_tokens
- 消费方：设置页「用量统计」现读现算不缓存（账本文件即唯一事实），允许手工编辑（坏行跳过）
- 发送前清理孤立 Unicode 代理对（防 400）
