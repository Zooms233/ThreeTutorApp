## 常驻调试手段

| 手段 | 位置 | 说明 |
|---|---|---|
| USAGE.jsonl 账本 | 数据根目录 | 每次成功 LLM 调用一行（time/course/lesson/scene/input/output/cacheRead/reasoning）。排查「某场景是否发出、是否成功」的第一入口：失败请求不入账 |
| stdout 用量行 | 调试控制台 | `LlmClient._logUsage` 每次调用打一行：入=命中+写入、出（含思考）、命中率、耗时，及实例累计 |
| busy 静态表 | `TutorChatService._busy` | 跨页面共享的生成中状态（课程名 → 文案）。退出重进聊天页仍能看到进行中状态；卡在非空即有请求未返回 |
| 兜底 toast | 群聊页 `_handleLessonAction` / `_sendMessage` | 非 LlmException 异常也会 toast 显示（不再静默失败），并注明重试方式 |

## messages 拼接跟踪（trace，临时代码）

**用途**：验证发给 LLM 的 messages 拼接是否正确——每轮实际发送前打印结构快照（角色序列 + 简化标签，不含全文）。配合 agent 翻书（`read_textbook`）可观察：翻书轮次是否追加了 `assistant(tool_calls)` + `tool(教材)` 消息、下一轮是否完整重放、各场景 system 组合差异。

**位置**：`TutorChatService._traceMessages()`，在统一出口 `_chatLogged` 发请求前调用；开关 `static const _traceEnabled = true`。

**输出示例**（stdout `[trace]`）：

```
[trace] 上课#1 带工具 4条
  [0] system（teaching.md：教学规则+导师档案[苏格拉底]+学习者+状态+进度+日期+教材当前节+目录（3421字））
  [1] 用户消息1「熵增原理是什么来着？」
  [2] assistant（翻书：第三章.md > 3-4 熵增定律）
  [3] tool（教材，2876字）
```

说明：

- system 由 `_describeSystem` 识别规则文件（teaching/qa/social/group/update/learner_extra）+ 拼装块，可对比不同场景组合差异
- 用户消息按单次请求内出现顺序编号，历史重放后编号自然连续（能看出追加）
- `带工具/不带工具` 标志可验证「末轮强制不带工具」逻辑
- **验证完置 `_traceEnabled = false` 或删除该方法**（临时代码，不参与正式调试）

## 历史排查案例（2026-09-08 遗传学「课后更新静默失败」）

排查路径可复用：**先看 USAGE 账本确定哪段链路没入账** → 页面加通用 catch 让错误可见 → 对嫌疑环节加探针（如请求体编码诊断、响应原文落盘）→ 对照服务商文档确认。当时两个根因：`?maxTokens: maxTokens` null-aware 语法笔误把值 4096 当成键（仅更新场景触发）；DeepSeek JSON Output 模式概率性返回空 content（已改走提示词约束 + `_extractJson` 容错解析路线）。
